## 🛠 Технологический стек

Проект разделен на две экосистемы, каждая из которых использует лучшие современные практики и инструменты:

### 🔵 Экосистема C++ (Лабы 1, 4)
- **Стандарт:** C++20
- **Сборка:** CMake (с автоматической подтяжкой зависимостей через `FetchContent`)
- **Тестирование:** Google Test (GTest)
- **Анализ покрытия:** `lcov`
- **Линтер:** `cppcheck`

### 🟡 Экосистема Python (Лабы 2, 3)
- **Стандарт:** Python 3.11+
- **Тестирование:** `pytest` + `pytest-cov`
- **Статический анализ:** `mypy` (строгая типизация)
- **Линтер и форматирование:** `ruff`
- **Сборка:** `PyInstaller` (генерация `.exe` артефактов)

## ⚙️ Инженерные практики и архитектура

Особое внимание в проекте уделено качеству кода и инфраструктуре:

1. **Кроссплатформенный CI/CD (GitHub Actions):** Настроен сложный пайплайн, который параллельно тестирует C++ код на Ubuntu-раннерах и Python код на Windows-раннерах. При пуше в `main` автоматически собираются бинарники (`.exe` и исполняемые файлы Linux) и публикуются в релизы.
2. **Максимальное покрытие тестами:** Каждая предметная область покрыта модульными тестами **более чем на 90%** (фактически 100% для сложных структур вроде итераторов графа). CI настроен на падение (`fail-under`), если покрытие падает ниже порога.
3. **Изоляция CLI:** Бизнес-логика строго отделена от консольного интерфейса. Ядро программ можно переиспользовать в GUI или Web без переписывания.
4. **Git Flow:** Прямые коммиты в `main` запрещены. Разработка ведется исключительно в `feat/`-ветках с последующим код-ревью и слиянием через Pull Request (PR) только после "зеленых" галочек от пайплайна.
5. **Чистота репозитория (`.gitignore`):** В истории коммитов хранится строго исходный код. Никаких `cmake-build-debug`, `.pytest_cache`, `.DS_Store` или `.idea`.

## 🚀 Запуск и проверка

Проект полностью отвязан от конкретной среды разработки (IDE) и готов к запуску.

### Вариант 1: Быстрый тест (Releases)
Вам не нужно устанавливать компиляторы или Python. Просто перейдите во вкладку [Releases](../../releases) справа и скачайте готовый исполняемый файл для нужной лабораторной работы.

### Вариант 2: Локальная сборка
Детальные инструкции по сборке из исходников через `CMake` или запуску через интерпретатор Python находятся внутри папок `labX/README.md`. Общий принцип:
* Для C++: `cmake -B build && cmake --build build`
* Для Python: `python -m labX.cli` (с корня репозитория).
