## 📚 Документация

Папка `docs/` является артефактом сборки и **генерируется пользователем самостоятельно**. В репозитории хранится только файл настроек `Doxyfile` и исходный код с подробными комментариями в формате Doxygen.

### Гайд по созданию документации:

1. Убедитесь, что в вашей системе установлена утилита Doxygen:
    - **macOS:** `brew install doxygen`
    - **Linux (Ubuntu/Debian):** `sudo apt install doxygen`
    - **Windows:** Скачайте установщик с официального сайта.
2. Откройте терминал и перейдите в директорию четвёртой лабораторной работы:
   ```bash
   cd lab4
   ```
3. Запустите генерацию, передав конфигурационный файл:
   ```bash
   doxygen Doxyfile
   ```
4. Утилита автоматически создаст папку `docs/`. Перейдите в неё и откройте главный файл сайта в браузере:
   ```bash
   open docs/html/index.html
   ```

## Возможности классов и алгоритмов

### 1. Обобщённые сортировки (Heapsort и Stooge sort)
- Реализованы в виде шаблонных функций, не зависящих от конкретного типа данных.
- Работают со стандартными динамическими коллекциями (например, `std::vector`).
- Поддерживают сортировку как примитивных встроенных типов, так и сложных пользовательских объектов.
- Позволяют передавать пользовательское лямбда-выражение (компаратор) для изменения логики сортировки (например, по убыванию).

### 2. Пользовательский тип (FlightInfo)
- Демонстрационный класс авиарейса (хранит номер, дистанцию полёта и приоритет).
- Перегружены все операторы сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`).
- Перегружены потоковые операторы ввода и вывода (`<<`, `>>`) с проверкой корректности данных.

### 3. Обобщённый контейнер Graph<T> (Структура Вирта)
- Представляет собой **ориентированный граф**, реализованный как связный список вершин, где каждая вершина содержит собственный список смежных вершин (исходящих рёбер).
- Полное управление памятью и ресурсами в соответствии с правилом пяти (Rule of Five), включая Move-семантику.
- Методы для проверки наличия, добавления и удаления вершин и рёбер, а также вычисления их степеней.
- **Итераторы:** Реализованы 4 типа пользовательских двунаправленных итераторов, совместимых с STL:
    - Итератор вершин (`vertex_iterator`).
    - Итератор всех рёбер графа (`edge_iterator`).
    - Итератор инцидентных рёбер конкретной вершины (`incident_iterator`).
    - Итератор смежных вершин (`adjacent_iterator`).
    - Для всех итераторов предусмотрены константные (`const_`) и реверсивные (`reverse_`) адаптации.
- Исключительная безопасность (Exception Safety): защита от несуществующих узлов и дубликатов через выброс `std::invalid_argument`.

## Сборка

Проект собирается из консоли с использованием **CMake**. Библиотека тестов (Google Test) загружается автоматически.

**Linux / macOS:**
```bash
cd lab4
cmake -S . -B build
cmake --build build -j$(nproc)
```

**Windows (Visual Studio / MSVC):**
```powershell
cd lab4
cmake -S . -B build
cmake --build build --config Release
```

## Запуск консольного приложения

Точка входа и интерактивное меню изолированы в модуле `src/`. Меню разделено на два блока (для сортировок и графов). После сборки запустите исполняемый файл:

**Linux / macOS:**
```bash
./build/lab4_app
```

**Windows:**
```powershell
.\build\Release\lab4_app.exe
```

## Тестирование

Проект покрыт модульными тестами на базе **Google Test** с покрытием целевой логики 100%. Запуск всех тестов выполняется командой:

```bash
cd build
./lab4_tests
```

## CI/CD

Проект интегрирован в общий многоплатформенный пайплайн на GitHub Actions (`.github/workflows/ci.yml`), который при каждом пуше автоматически:
- устанавливает зависимости с кэшированием (GTest);
- выполняет статический анализ кода линтером **cppcheck**;
- собирает проект и запускает unit-тесты;
- собирает покрытие кода утилитой **lcov** (исключая служебные файлы и тесты);
- собирает бинарные артефакты и публикует их в **Releases** репозитория.
