## 📚 Documentation

The `docs/` folder is a build artifact and **is generated by the user**. The repository maintains only the `Doxyfile` configuration and Doxygen-formatted source code comments.

### Guide to Generating Documentation:

1. Ensure the Doxygen utility is installed on your system:
    - **macOS:** `brew install doxygen`
    - **Linux (Ubuntu/Debian):** `sudo apt install doxygen`
    - **Windows:** Download the installer from the official Doxygen website.
2. Open a terminal and navigate to the directory of the fourth laboratory work:
   ```bash
   cd lab4
   ```
3. Run documentation generation using the configuration file:
   ```bash
   doxygen Doxyfile
   ```
4. The tool automatically creates the `docs/` directory. Open the documentation index in your browser:
   ```bash
   open docs/html/index.html
   ```

## Features & Capabilities of Classes and Algorithms

### 1. Generic Sorting Algorithms (Heapsort and Stooge Sort)
- Implemented as template functions independent of concrete data types.
- Compatible with standard dynamic collections (`std::vector`, `std::array`) and classic C-style arrays (`T[]` as well as pointer-size pairs `T* arr, std::size_t n`).
- Support sorting of built-in primitive types as well as complex user-defined objects.
- Accept custom lambda expressions (predicates / comparators) to tailor sorting order (e.g., descending order).

### 2. User-Defined Class (FlightInfo)
- Demonstrative flight model class storing flight code, flight distance, and priority.
- Overloads all relational comparison operators (`==`, `!=`, `<`, `>`, `<=`, `>=`).
- Overloads stream I/O operators (`<<`, `>>`) with strict validation (negative distances or invalid priorities set the stream's `failbit`).

### 3. Generic Container Graph<T> (Wirth's Structure)
- Implemented as a **directed graph** based on Wirth's structural model: a linked list of vertices (`std::list`), where each vertex node maintains vertex data and a linked list of outgoing directed edges / adjacent nodes.
- Full memory and resource management adhering to the Rule of Five, including Move semantics.
- Exposes standard STL type aliases (`value_type`, `reference`, `const_reference`, `pointer`, `const_pointer`, `size_type`, `difference_type`, `edge_type`).
- Overloads all **6 container comparison operators** (`==`, `!=`, `<`, `>`, `<=`, `>=`).
- Supports computation of vertex degree (`vertex_degree`) and edge degree (`edge_degree`).
- Vertex and edge deletion implemented by value (`val`) and by iterator (`vertex_iterator`, `edge_iterator`, `const_vertex_iterator`, `const_edge_iterator`) with strict guards against invalid or `end()` iterators.
- Stream output `operator<<` built strictly using graph iterators (`v_cbegin`, `v_cend`, `adj_cbegin`, `adj_cend`) and the generic algorithm `std::for_each`.
- **Iterators:** Full spectrum of STL-compatible iterators:
    - Vertex iterators (`vertex_iterator`, `const_vertex_iterator`, `reverse_vertex_iterator`, `const_reverse_vertex_iterator`).
    - Whole-graph edge iterators (`edge_iterator`, `const_edge_iterator`, `reverse_edge_iterator`, `const_reverse_edge_iterator`).
    - Incident edge iterators for a specific vertex (`incident_iterator`, `const_incident_iterator`, `reverse_incident_iterator`, `const_reverse_incident_iterator`).
    - Bidirectional adjacent vertex iterators (`adjacent_iterator`, `const_adjacent_iterator`, `reverse_adjacent_iterator`, `const_reverse_adjacent_iterator`).
    - **Forward adjacent vertex iterator** (`forward_adjacent_iterator`, `const_forward_adjacent_iterator`) specifying the iterator category tag `std::forward_iterator_tag` (in accordance with variant 2.1.12 requirements).
    - All iterators implement prefix and postfix `operator++` and `operator--` (for bidirectional iterators), alongside safe `operator==` comparisons for past-the-end bounds.
- Exception Safety: robust protection against non-existent nodes, edges, or duplicate insertions by throwing `std::invalid_argument`.

## Building the Project

The project is built via **CMake**. The Google Test framework is fetched and configured automatically.

**Linux / macOS:**
```bash
cd lab4
cmake -S . -B build
cmake --build build -j$(nproc)
```

**Windows (Visual Studio / MSVC):**
```powershell
cd lab4
cmake -S . -B build
cmake --build build --config Release
```

## Running the Console Application

The entry point and interactive menu are located in the `src/` module. The menu is divided into two operational modules (sorting algorithms and graph operations). After building, run the compiled binary:

**Linux / macOS:**
```bash
./build/lab4_app
```

**Windows:**
```powershell
.\build\Release\lab4_app.exe
```

## Testing

The project is covered by automated unit tests on **Google Test** with 100% target business logic coverage. Run the test suite with:

```bash
cd build
./lab4_tests
```

## CI/CD

The project is integrated into the multi-platform GitHub Actions workflow (`.github/workflows/ci.yml`), which automatically:
- Installs dependencies and caches Google Test;
- Runs static code analysis via the **cppcheck** linter;
- Compiles the project and runs all unit tests;
- Collects test coverage with **lcov** (excluding third-party headers and test drivers);
- Packages standalone binary artifacts and publishes them to **GitHub Releases**.
