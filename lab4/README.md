## 📚 Документация

Папка `docs/` является артефактом сборки и **генерируется пользователем самостоятельно**. В репозитории хранится только файл настроек `Doxyfile` и исходный код с подробными комментариями в формате Doxygen.

### Гайд по созданию документации:

1. Убедитесь, что в вашей системе установлена утилита Doxygen:
    - **macOS:** `brew install doxygen`
    - **Linux (Ubuntu/Debian):** `sudo apt install doxygen`
    - **Windows:** Скачайте установщик с официального сайта.
2. Откройте терминал и перейдите в директорию четвёртой лабораторной работы:
   ```bash
   cd lab4
   ```
3. Запустите генерацию, передав конфигурационный файл:
   ```bash
   doxygen Doxyfile
   ```
4. Утилита автоматически создаст папку `docs/`. Перейдите в неё и откройте главный файл сайта в браузере:
   ```bash
   open docs/html/index.html
   ```

## Возможности классов и алгоритмов

### 1. Обобщённые сортировки (Heapsort и Stooge sort)
- Реализованы в виде шаблонных функций, не зависящих от конкретного типа данных.
- Работают как со стандартными динамическими коллекциями (`std::vector`, `std::array`), так и с классическими C-массивами (`T[]`, а также через пару `T* arr, std::size_t n`).
- Поддерживают сортировку как примитивных встроенных типов, так и сложных пользовательских объектов.
- Позволяют передавать пользовательское лямбда-выражение (компаратор) для изменения логики сортировки (например, по убыванию).

### 2. Пользовательский тип (FlightInfo)
- Демонстрационный класс авиарейса (хранит номер, дистанцию полёта и приоритет).
- Перегружены все операторы сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`).
- Перегружены потоковые операторы ввода и вывода (`<<`, `>>`) со строгой валидацией корректности данных (отрицательная дистанция или приоритет вызывают `failbit`).

### 3. Обобщённый контейнер Graph<T> (Структура Вирта)
- Представляет собой **ориентированный граф**, реализованный на основе структуры Вирта: связный список вершин (`std::list`), где каждый узел содержит данные вершины и список исходящих дуг/смежностей.
- Полное управление памятью и ресурсами в соответствии с правилом пяти (Rule of Five), включая Move-семантику.
- Поддерживает полный набор стандартных типов-псевдонимов STL (`value_type`, `reference`, `const_reference`, `pointer`, `const_pointer`, `size_type`, `difference_type`, `edge_type`).
- Перегружены все **6 операторов сравнения контейнеров** (`==`, `!=`, `<`, `>`, `<=`, `>=`).
- Поддерживает вычисление степени вершины (`vertex_degree`) и степени ребра (`edge_degree`).
- Удаление вершин и рёбер реализовано как по значению (`val`), так и по итераторам (`vertex_iterator`, `edge_iterator`, `const_vertex_iterator`, `const_edge_iterator`) со строгой защитой от невалидных и `end()`-итераторов.
- Текстовый вывод `operator<<` построен исключительно с использованием итераторов графа (`v_cbegin`, `v_cend`, `adj_cbegin`, `adj_cend`) и обобщённого алгоритма `std::for_each`.
- **Итераторы:** Реализован полный спектр STL-совместимых итераторов:
    - Итератор вершин (`vertex_iterator`, `const_vertex_iterator`, `reverse_vertex_iterator`, `const_reverse_vertex_iterator`).
    - Итератор всех рёбер графа (`edge_iterator`, `const_edge_iterator`, `reverse_edge_iterator`, `const_reverse_edge_iterator`).
    - Итератор инцидентных рёбер конкретной вершины (`incident_iterator`, `const_incident_iterator`, `reverse_incident_iterator`, `const_reverse_incident_iterator`).
    - Двунаправленный итератор смежных вершин (`adjacent_iterator`, `const_adjacent_iterator`, `reverse_adjacent_iterator`, `const_reverse_adjacent_iterator`).
    - **Однонаправленный итератор смежных вершин** (`forward_adjacent_iterator`, `const_forward_adjacent_iterator`) со спецификацией категории `std::forward_iterator_tag` (согласно требованиям варианта 2.1.12).
    - Для всех итераторов реализованы префиксные и постфиксные `operator++` и `operator--` (для двунаправленных), а также безопасное сравнение `operator==` для конечных итераторов.
- Исключительная безопасность (Exception Safety): защита от несуществующих узлов, ребер и дубликатов через выброс `std::invalid_argument`.

## Сборка

Проект собирается из консоли с использованием **CMake**. Библиотека тестов (Google Test) загружается автоматически.

**Linux / macOS:**
```bash
cd lab4
cmake -S . -B build
cmake --build build -j$(nproc)
```

**Windows (Visual Studio / MSVC):**
```powershell
cd lab4
cmake -S . -B build
cmake --build build --config Release
```

## Запуск консольного приложения

Точка входа и интерактивное меню изолированы в модуле `src/`. Меню разделено на два блока (для сортировок и графов). После сборки запустите исполняемый файл:

**Linux / macOS:**
```bash
./build/lab4_app
```

**Windows:**
```powershell
.\build\Release\lab4_app.exe
```

## Тестирование

Проект покрыт модульными тестами на базе **Google Test** с покрытием целевой логики 100%. Запуск всех тестов выполняется командой:

```bash
cd build
./lab4_tests
```

## CI/CD

Проект интегрирован в общий многоплатформенный пайплайн на GitHub Actions (`.github/workflows/ci.yml`), который при каждом пуше автоматически:
- устанавливает зависимости с кэшированием (GTest);
- выполняет статический анализ кода линтером **cppcheck**;
- собирает проект и запускает unit-тесты;
- собирает покрытие кода утилитой **lcov** (исключая служебные файлы и тесты);
- собирает бинарные артефакты и публикует их в **Releases** репозитория.
